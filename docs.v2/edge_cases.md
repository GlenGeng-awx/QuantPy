# Edge Cases — LLM 踩过的坑 (防再犯清单)

> 本文件 = 错误的模式化记录: 每条 = 病 (我犯过什么) → 律 (防再犯规则)。
> 正文 docs 保持终态纯净 (错误叙事不进正文); SESSION_LOG 记事件流, 这里只留规则化的结论。
> 开工时随 notes.md 一起读; 新 case 追加在对应分节 (编号递增)。

## 写作漂移 (格式病)

- **EC-01 "一句话"独立节** (三犯: ORCL/MU/TTD/NFLX 原生 + SE 盲跑复发): L1 分卡长出 `## 一句话` / `## §1 一句话定义` 节 — 七问清单第 1 条只是问题名不是节式。**律: L1 分卡结构 = 先说结论 + 正文 + 附录三段即全部 (L1_00); 体检必查 `grep '^## 一句话' L1_0[1-8]*.md` = 0。**
- **EC-02 摘要超长** (SE 盲跑复发 643 字; 前有五链 500-600): 结论段越写越厚, 恶化/解决分支、双层展开全挤进摘要。**律: 生成后立即量字 (渲染口径: 段 2-4 / 每段一整行 ≤300 / 总 ≤450), 不等用户抓。**
- **EC-03 导览行变体** (ORCL 用 "30 秒:" 而非 "30 秒导览:"): 同一废料两种写法。**律: 清扫用双 pattern `grep '30 秒'`。**

## 协作流程病

- **EC-04 发现问题直接动手** (犯于本轮: 发现 "一句话" 根因后未经确认一口气改了 SE 八卡 + L1_00 + SESSION_LOG): notes 明令 "先 align 再动手"。**律: 发现任何问题 → 先报告 (现象/根因/修复方案) → 等用户裁 → 动手; 修复方案本身是 brainstorm 对象。**
- **EC-05 SESSION_LOG 追加变替换** (三犯): 追加新判例时整条替换掉旧条目 (丢 ADBE 体检条 / ORCL 收官条 / 摘要形态条)。**律: SESSION_LOG 只准后插新条, 禁 replace 既有条目; 改完 `grep -c '^- \*\*'` 对账条数。**
- **EC-06 偏好泛化成机械规则** (两犯: "整段散文唯一合法" / "行 ≤75 硬限" — 都被用户打回): 把用户一个具体反馈推导成死规则。**律: 规范的字面值以用户确认的原话为准, 不自行推导收紧; 不确定 = 问。**

## md 渲染层病

- **EC-07 忘记用户看的是 IDE 渲染** (核心判例): 段内换行渲染时被合并 (拆行是无效功); blockquote 内相反 (换行保留)。**律: 一切格式自查按渲染效果想象; 普通段落控制"行"的唯一手段 = 空行分段。**

## 工具病

- **EC-08 webfetch 取 PDF = 文本损坏** (SE 实战: 35% replacement chars, zlib 全毁): 文本化管道毁二进制。**律: PDF 用 curl 下载原始字节 + pdfplumber 解析; PDF 官方直读是 L2 财报周的最硬数据源。**

## Git 病

- **EC-09 误 commit 污染用户 history** (犯于本轮): 自作主张 commit 了 4 个。**律: 永不 commit/push (notes.md); 工作产物进 .gitignore。**

## 修改操作病

- **EC-10 重编号不 grep 跨卡引用** (犯于 MU: L1_01 §1 删节后 §2-§7 重编号, L3_01 两处 `L1_01 §2/§3` 引用随之错位): 分卡节号是跨卡锚点。**律: 动任何节号 → `grep -rn 'Lx_0N §' 全链` 对账引用。**
- **EC-11 体检清单不完整** (犯于 SE: 终验收跑了字数/结构/导览, 漏了"一句话节残留"检查 — 该链当轮就被漏检项反噬): 检查项凭记忆拼, 每次不一样。**律: 链级体检跑固定清单 (字数/段形态/一句话节/导览双 pattern/现价/层门/五件套/硬规则/跨卡引用), 全过才算完 — 清单见 L4 终检 + 本文件各项 grep 命令。**
- **EC-12 agenda 抢跑** (犯于 KB 段: 用户给 agenda"做一步看一步", 我连跑 protocol→index→两条 KB 三步): 与 EC-04 (发现即改) 同族异型 — 这是"执行序列抢跑"。**律: 用户给 agenda = 单步执行等 review; 后续步骤显式标 (等你点头)。**

## Doc 写作病

- **EC-13 deco 叙事残留** (犯于 L2_00: 废除判例注"第 7 条旧版已废除…"写进正文): 错误的"墓志铭"式注释污染终态。**律: deco = 删除, 不留 stub 不留叙事; 演化史只进 SESSION_LOG。**
- **EC-14 终态 doc 三删不彻底** (犯于 protocol 首版 + 本轮 L1_00 括注: "为什么没选 X"类叙事混进 doc): 终态 spec 里混入历史机制/跨 doc 对照/决策叙事。**律: doc 只写"现在是什么"; "为什么变成这样"归 SESSION_LOG, "怎么防再犯"归本文件。**
- **EC-17 落盘前跳过 notes 自查** (两犯: 00_framework 新尾注"任何物理执行不得改变逻辑结果"决策叙事 + §0.2 括注下放去向清单, 均被用户以 "修改 docs 以后, 需要看 notes" 抓回): notes 的终态三删/长行规则嘴上知道、手上没执行; 病根 = 把 notes 当起手读物而非落盘前检查表。**律: 每次 docs 落盘前显式过一遍 notes §文档维护 + §可读性 (终态三删 / 长行 / 巨长括注), 与格式自查 (节号/跨卡引用/孤儿残句) 同批跑。**

## 规则改版病

- **EC-15 判例落地范围枚举不全** (犯于 11/20 渲染判例的执行: 五链重排只覆盖 L1 摘要, MU 链 8 张 L2 "先说结论" 的 "三句:" 碎片 + L2_05 头部空行断块漏网, 直到用户报 L2_05 格式才暴露): 与 EC-10/11 同族 — 覆盖范围靠可见重灾区, 不靠枚举。**律: 规则改版落地时先枚举全部受影响位置类型 (L1 摘要 / L2 先说结论 / 头部 blockquote / L3 导读), 旧链回扫用 grep 形态签名 (`^三句:$` / 头部断块 pattern), 禁抽检; 层门检查项同步补盲侧 (版式 #14 已补 "空行断块" 查)。**
- **EC-16 subagent 空返回的三步排查协议** (犯于 NVDA L2: 同一写作任务连死 3 次 — 9 卡/4 卡/1 卡粒度, 返回 " CSV"/"输入"等碎片或空, 无落盘): subagent 死亡时禁止直接重派 — 病因可能不是任务体量。**律: 排查按序: ① 内容探针 (分段喂输入文件, 排敏感内容) ② 简单任务探针 (读+短汇报, 排 subagent 通道本身) ③ 生成型探针 (写小文件落盘 + 全域 find, 排写盘能力与路径 typo — 注意 EC-16a) — 三探针过而重任务死 = 约束密度问题, 降约束 (自然语言化 prompt/减自查清单/单文件粒度) 重试。**
- **EC-16a (并入 EC-16 律 ②③, 独立记录因三犯史)**: subagent 汇报 "落盘 OK" ≠ 文件在预期目录 — 手写路径 typo 会把它送进影子目录。
