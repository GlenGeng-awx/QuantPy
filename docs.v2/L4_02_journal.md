# L4_02 journal: 用户备忘录 (可选层件)

> **产出**: `L4_02_journal.md` = 用户个人观点与关注事实的记录 — **可选, 默认空** (有必要才建, 没有兴趣点可以整条链不出现此文件)。
>
> **与 L4 两件套的关系**: 独立并存, 互不改写 — 链内裁决 (L4_00/L4_01) 不引用不吸收 journal; journal 也不改写裁决。冲突留张力 (可能正是价值所在)。
>
> **不进 §L4 终检**: 非框架产出, 纯用户层。

## 协议 (标号语义)

- **标号固定主题**: 每个号绑定一个主题, 启用后不复用
- **新增 = append only (新号)**: 新主题开新号, 不插入旧号之间
- **老条目 = 原地 update**: 观点可改写, 事实可补充 (与链的 "锁定不改" 相反 — journal 允许后悔)
- 内容不保证公平、不保证与链内裁决一致

## 产出格式

```
# {STOCK} — L4_02 journal (用户备忘录)

> **性质**: 用户个人观点记录 — 不保证公平、不保证与链内裁决一致。
>
> **协议**: 标号固定主题; 新增条目 append only (新号); 老条目原地 update (观点可改写, 事实可补充)。
>
> **与 L4_00/L4_01 关系**: 独立并存, 互不改写 — 冲突留张力。

## 1. {主题}

{内容: 观点与事实自由混排; 引链内数字时注明出处 (票/卡), 便于日后对账}
```

## 写作纪律

- **观点与事实混排是特性**: 不必像 L1 那样中立白描 — 这是用户的声音, 立场是内容的一部分
- **引用链内证据时带指针**: 如 "(L3_03 ②#2, VerityData)" — 半年后重读时能回到证据源
- **update 与 append 的判别**: 事实补充/观点修正 → 改老号; 新话题 (新事件/新关注点) → 开新号
- 重跑全链时 journal 保留 (用户层资产, 不随框架链刷新被覆盖)
