# Edge Cases — LLM 踩过的坑 (防再犯清单)

> 本文件 = 错误的模式化记录: 每条两行 — **病** (犯过什么, ≤~60 字, 保留链名定位) / **律** (可执行动作或 grep, 加粗)。
>
> 犯案过程的叙事细节归 SESSION_LOG; 正文 docs 保持终态纯净。新 case 按犯案时机入节, 编号递增不复用。

## 生成病 (跑链写产出时犯)

- **EC-01 "一句话"独立节** (ORCL/MU/TTD/NFLX 原生 + SE 盲跑复发, 共三犯)
  病: L1 分卡长出 `## 一句话` 节 — 七问清单第 1 条是问题名不是节式。
  **律: L1 分卡结构 = 先说结论 + 正文 + 附录三段即全部 (L1_00); 体检必查 `grep '^## 一句话' L1_0[1-8]*.md` = 0。**

- **EC-02 摘要超长** (SE 盲跑 643 字; 前有五链 500-600)
  病: 结论段越写越厚, 分支细节全挤进摘要。
  **律: 生成后立即量字 (渲染口径: 段 2-4 / 每段一整行 ≤300 / 总 ≤450), 不等用户抓。**

- **EC-03 导览行变体** (ORCL: "30 秒:" 而非 "30 秒导览:")
  病: 同一废料两种写法。
  **律: 清扫用双 pattern `grep '30 秒'`。**

- **EC-07 忘记用户看的是 IDE 渲染** (核心判例, 多链)
  病: 源码看是两段, 渲染是一行 — 文本级自查管不了渲染结构。
  **律: 一切格式自查按渲染效果想象; 普通段落控制"行"的唯一手段 = 空行分段。**

- **EC-08 webfetch 取 PDF = 文本损坏** (SE: 35% replacement chars)
  病: 文本化管道毁二进制。
  **律: PDF 用 curl 下载原始字节 + pdfplumber 解析; PDF 官方直读是 L2 财报周的最硬数据源。**

- **EC-11 体检清单不完整** (SE: 漏"一句话节残留"检查, 当轮被反噬)
  病: 检查项凭记忆拼, 每次不一样。
  **律: 链级体检跑固定清单 (字数/段形态/一句话节/导览双 pattern/现价/层门/五件套/硬规则/跨卡引用), 全过才算完 — 清单见 L4 终检 + 本文件各项 grep 命令。**

- **EC-20 表格数值格心算** (0700HK/ADBE/ORCL/SE/TTD 等多链, 18 格方向错, 两轮)
  病: 价格侧枚举标签手算百分比, 方向反复颠倒 (拿"上沿−现价"当"贵%"), 无验证落盘。
  **律: 表格数值格一律机械算 — python 出数只抄不心算, 改完复扫全表 (算式定义见 L3_00 §4 价格侧表)。**

- **EC-21 修复引入次生病** (修断块造出连续空 `>`; 前科: 修价格侧又造方向错)
  病: 修复动作本身制造新病, 裸修不验。
  **律: 每轮修正后必须复扫受影响全表 — 修复脚本带终验, 修完不验 = 未完成。**

## 改版病 (改 docs/规则时犯)

- **EC-10 重编号不 grep 跨卡引用** (MU: L1_01 §1 删节后重编号, L3_01 引用错位)
  病: 分卡节号是跨卡锚点。
  **律: 动任何节号 → `grep -rn 'Lx_0N §' 全链` 对账引用。**

- **EC-13 deco 叙事残留** (L2_00: 废除判例注写进正文)
  病: "墓志铭"式注释污染终态。
  **律: deco = 删除, 不留 stub 不留叙事; 演化史只进 SESSION_LOG。**

- **EC-14 终态 doc 三删不彻底** (protocol 首版 + L1_00)
  病: "为什么没选 X" 类决策叙事混进 doc。
  **律: doc 只写"现在是什么"; "为什么变成这样"归 SESSION_LOG, "怎么防再犯"归本文件。**

- **EC-15 判例落地范围枚举不全** (11/20 渲染判例: 只覆盖 L1 摘要, MU 链 L2 碎片漏网)
  病: 覆盖范围靠可见重灾区, 不靠枚举。
  **律: 规则改版落地时先枚举全部受影响位置类型 (L1 摘要 / L2 先说结论 / 头部 blockquote / L3 导读), 旧链回扫用 grep 形态签名, 禁抽检; 层门检查项同步补盲侧。**

- **EC-17 落盘前跳过 notes 自查** (00_framework/L1_07 等三犯)
  病: notes 规则嘴上知道手上没执行; 自查是文本级 grep 管不了渲染结构。
  **律: docs 落盘前显式过 notes §文档维护 + §可读性, 自查含渲染层 — 连续 `>` 行 = 同段渲染, blockquote 语义段间必须空 `>` 行; 分段粒度 = 语义大段不是句子; 引号跨行首尾各一次。**

- **EC-22 形态签名追着上一场病跑** (连排→断块→连续空 `>`→单行挤语义, 四连漏均用户报)
  病: 检查器只记忆上一场病的形态, 新形态 (单行多语义) 不触发。
  **律: 扫描器形态枚举要"反向想象病" (不止修过的), 用户报新病 = 检查器缺一行 — 补进扫描器而非只修当处。**

- **EC-23 回扫范围枚举不全** (L3 修完没人想到 L2 也有; ADBE 问了才扫 ADBE)
  病: "回扫哪些文件"本身靠点名, 不靠全枚举。
  **律: 任何"全库回扫"类动作先 `glob` 列文件清单 (全层 L1-L4 × 全链), 清单即范围; 用户点名 ≠ 边界。**

## 协作病 (对用户时犯)

- **EC-04 发现问题直接动手** (SE 八卡一口气改)
  病: 未经确认动手, 连 SESSION_LOG 一起改。
  **律: 发现任何问题 → 先报告 (现象/根因/修复方案) → 等用户裁 → 动手; 修复方案本身是 brainstorm 对象。**

- **EC-12 agenda 抢跑** (KB 段: 连跑 protocol→index→两条 KB)
  病: 对 agenda 的执行序列越权 (区别于 EC-04 的发现问题即动手)。
  **律: 用户给 agenda = 单步执行等 review; 后续步骤显式标 (等你点头)。**

- **EC-18 用户裁了方向就当裁了落盘** (L1_00 重排等, 三犯 — 最近 L0_05 新建未 diff 落盘)
  病: 方向认可 ≠ 落盘认可, diff 从未给用户看。
  **律: docs 修改一律先给 diff (含新文件全文预览), 用户 "OK/落/改" 之后才动手; 用户没看过 diff 就落盘 = 抢跑, 与 EC-12 同族。**

- **EC-05 SESSION_LOG 追加变替换** (三犯)
  病: 追加新判例时整条替换掉旧条目。
  **律: SESSION_LOG 只准后插新条, 禁 replace 既有条目; 改完 `grep -c '^- \*\*'` 对账条数。**

- **EC-06 偏好泛化成机械规则** (两犯: "散文唯一合法" / "行 ≤75 硬限")
  病: 把用户一个具体反馈推导成死规则。
  **律: 规范的字面值以用户确认的原话为准, 不自行推导收紧; 不确定 = 问。**

- **EC-09 误 commit 污染用户 history**
  病: 自作主张 commit。
  **律: 永不 commit/push; 工作产物进 .gitignore。**

- **EC-19 绝对路径 = 越权面** (ISRG 影子目录 + /tmp 中间文件, 两犯)
  病: 习惯性拿系统临时目录当工作区。
  **律: 一切文件读写以 pwd 为根 — 命令用相对路径, 工具用 workdir 参数, 禁裸绝对路径; 中间/临时文件只落本仓库 tmp/; 越界需求 = 报告用户等处理。**

## subagent 病

- **EC-16 subagent 空返回三步排查** (NVDA L2: 同任务连死 3 次)
  病: 死亡任务直接重派, 病因可能不是任务体量。
  **律: 排查按序: ① 内容探针 (分段喂输入) ② 简单任务探针 (读+短汇报) ③ 生成型探针 (写小文件落盘 + 全域 find) — 三探针过而重任务死 = 约束密度问题, 降约束重试。**

- **EC-16a 落盘 OK ≠ 文件在预期目录** (三犯史: 影子目录)
  病: 手写路径 typo 把文件送进影子目录。
  **律: subagent 落盘 prompt 禁手写长绝对路径 (写前 `ls` 确认); 主 agent 每层收口后 `git status` 扫 untracked 防漏网。**
