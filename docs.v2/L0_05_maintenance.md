# L0_05 链维护: 四档选型 (成本 × freshness)

> 四档 = 已建链 (ai_report.v2/{STOCK}/ 26 文件) 的后续维护。选型与执行过程归本文件; dispatcher 只指方向, 用户裁后执行。
>
> **统一心智模型**: 所有 task = 同一条 L1→L2→L3→L4 演算管线 — 区别只在**输入与搜索量**: 档 4 的生成 (fresh run) 从 0 采集 (web 全量搜索, 贵); 档 1-3 拿着 existing report (证据已固化) 做演算 (不搜或小搜, 便宜)。四层 doc 是管线的 spec, 本文件是管线的调度器与各档执行过程。

## 四档表 (1-3 = 拿着现链演算的家族; 档 4 = 从零生成, 不含 1-3)

> 1-3 逐级包含: 任何档都包含档 1 (静态 review) — 档 2 = 档 1 + 价格, 档 3 = 档 2 + 消息面。
>
> 档 1 独立触发时跑全库 (EC-15); 作为被包含清单时跑本链。

| 档 | 触发原因 | 输入 | 搜索 | 演算 | 成本量级 |
|----|---------|------|------|------|---------|
| 1 静态 review | docs 更新 (增删列/改表述) | 现链 + 最新 docs | 0 | 全层校验演算 (见下) | ~$1-3 |
| 2 价格刷新 (= 1 + 价格) | daily 价格变动 | 现链 + EOD | 0 | 全层价格重演 (见下) | ~$2-4 |
| 3 web shadow (= 2 + 消息面) | 财报临近 / 预期有事件 | 现链 + 新闻 | 0 (扫描与 dispatcher 合一) | 时效判定演算 (见下) | ~$8-15 (五票复检) |
| 4 rerun | 框架大版本 / 重大事件 / 档 3 判定 | 0 (web 采集) | 全量 | rerun = fresh run + diff prevReport | ~$20 |

## 各档执行过程

> 所有档位遵守 00 §0.1 依赖图 (逻辑计划) + §0.1.5 执行节奏 (物理计划: 逐文件/回证据/隔离) — 维护 task 不豁免层间纪律, 只是管线更短。

### 档 1: 校验演算 (输入 = 现链 + 最新 docs)

逐层跑校验: L1 层门项复跑 (格式/渲染四病/证伪表) → L2 骨架行+insights 配额复验 + L2_07 矩阵格 python 复算 → L3 票字面骨架+hint 四段式 grep → L4 两卡数字一致对账。发现处即修 (格式/对账), 判定与数据不动 — "docs 新规格 vs 旧产出" 的差值收敛。

### 档 2: 价格重演 (输入 = 现链 + EOD; 先跑档 1 清单 — 本链)

EOD 重取 (本地 download) → **L2_08 §1 审计重跑** (三口径隐含 g 反推 + 市场先生状态 — 拿新价格重演那套方法, 不是改数字) → **L3_00 收口表价格侧列重算** (五票区间 vs 新 EOD, 机械算: 覆盖/贵/深水 + 两门计分) → **L4 当 fresh run 重演** (双门数数 → 合成矩阵出新裁决 → 裁决行/击球判定/持仓衔接重写; 公司门读数不变 — 慢变量, L3 锁定在挡, L4 无需感知) → 格票防线刀检 (E-peak: 跌进带 ≠ 便宜)。

产出: L2_08 / L3_00 价格侧 / L4 两件; L3 票与区间不动 (锁定)。三处同源律: 价格侧三处必须同 EOD 源。连续触发 ≥2 次仍无法裁决 → 建议档 4 (可能基本面已变)。

### 档 3: 时效判定 (输入 = 现链 + 新闻)

**时间窗扫描与 dispatcher 合一**: dispatcher 阶段新闻扫描即本档扫描, 落 `ai_report.v2/{STOCK}/tmp/{STOCK}_shadow_scan_{date}.md`; 日志分两段 — **raw 段** (headline/源/日期/一句事实 — 五票复检的输入) + **结论段** (主 agent 路由记录, 复检 subagent 禁读, 防路由结论污染)。

扫描后三件:
- **档 2 照跑 (含档 1 清单)**: 档 1 校验 (本链) + L2_08 §1 审计 / L3_00 价格侧 / L4 重演 (per-file diff 照旧)。
- **L3 五票隔离复检** (派发契约本体 = L3_00 §3 复检态): 每票一个 subagent, 输入 = 扫描 raw 段 + 最新 EOD + 契约阅读清单; 输出 {维持 | 翻案信号}。翻案信号不改票 (写后锁定) — = 建议档 4, 用户裁; 全维持 → 记档。收口 = 主 agent 落 L3_00 复检记录 + tmp 详表。
- **路由去单点**: "轻量/重大" 不归主 agent 单点判 — 五票各自判新证据对自己的票重不重要; 任一翻案信号 → 建议档 4。链内判定与数字不动 — 档 3 不是 "mini rerun", 是 "信息增量检测" (检测权从主 agent 单点 → 五票大师镜头)。

### 档 4: rerun (fresh run + diff prevReport)

① 先不管旧链 (X.date 归档链), 独立生成新链 — 不读旧版本; ② 生成完 diff 新旧两版 report, 差异 flag 给用户看; ③ 用户说 OK 才拿 diff 结论回去修改新链 — diff 前禁读归档链。

## Dispatcher (推荐档位 — 输入: report 现状 + 最新价格 + 新闻扫描)

| 信号 | 推荐档 |
|------|--------|
| docs 有更新 (增删列/改表述) | 1 静态 review (全库) |
| 价格变化不大 (<~5% 且未穿带) | 不跑, 记一行观察 |
| 价格变化大 / 穿带 / 穿击球线 | 2 价格刷新 |
| 有事件 (非财报级: 诉讼进展/竞品动态/监管) | 3 时效判定 (shadow) |
| 财报 / C-level / SEC-DOJ 级事件 | 4 全链重跑 |

> 读入对象: report 的 L3_00 收口表 (区间 vs 最新 EOD — 机械算) + L4_00 触发器表 (翻案阈值) + L1_08 裁决日历 (到期事件) + 新闻扫描 (~10 轮, 即档 3 时间窗扫描 — 日志落链内 tmp/, 分 raw/结论两段, 见档 3)。输出 = 一句推荐 + 依据, 用户裁后执行。
> 加读: 链 L4_00 头部 "docs 对齐" 标注 — 对齐日 < docs 最近修法日 → 推荐档 1 (本链; lazy 收敛触发点 = 用户 dispatch 询问或档 2/3 执行, 先到者)。

## 执行纪律 (通用)

- 表格数值格一律机械算 (python 出数只抄不心算, 改完复扫全表 — L3_00 §4 价格侧算式律)。
- 档 1 独立触发跑全库 (docs 更新事件, 禁抽检 — EC-15); 档 2/3 内嵌的档 1 清单跑本链, 档 2/3 本身跑单链。
- 每档执行后 SESSION_LOG 记一行 (档位/标的/发现)。
- **修改即 diff**: 档 1-3 触碰 report 文件时, 逐文件改完即发 per-file diff (新→旧对照或 git diff) 给用户, 发完直接落盘不等确认; 档 4 的链末 diff 不变 (fresh run 无逐文件修改语义)。
- 现价散落在 report 内是合法行为 (L2_08 锚定 + L4 触发器 + L3_00 价格侧列) — 不建全局价格中心, 管理靠档 2 三处同源律。
