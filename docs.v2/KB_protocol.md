# KB_protocol: 用户知识库 (knowledgeBase/) 的协议

> **产出**: `knowledgeBase/{NN}_{Title_Case_Slug}.md` (如 `01_GENIUS_Act.md` — 词首大写, 可读性优先) = 用户个人投资偏好与关注点的记录库 — 调研文章与笔记, 类 wiki。git 入库 (用户资产)。

## 一、定位与目的

中立分析住在每条链的 L1-L4 (LLM 可独立重跑刷新); **KB = 用户的声音** — 长期关注点、观点、调研过程、拍板过的结论, 事实与观点自由混排。

为什么存在: 有些话题横切多个标的 (一项立法/一种技术轨/一个行业结构会同时影响多家公司), 单条链装不下 — 话题需要自己的家, 并能被未来的分析引用。**问什么、问多深由用户决定 — 这本身就是能力圈的构建**; 曾经的观点也可能错, KB 是笔记不是档案 — 欢迎未来的 review、查漏补缺、推翻重写。

分界一问: "这个内容换个标的还成立吗?" — 成立 → 独立条目; 不成立 (绑定单一标的) → 并入相关话题条目, 挂钩小节标单标的。

## 二、写作约定

- **散文化, readable 优先** — 类 wiki/notes, 给现在的用户/将来的用户/LLM 三方读者, 新 comer 能读懂, 不预设上下文
- 开头一段引语说清 "这条讲什么 + 核心观点", 再展开
- 事实与观点混排 (笔记, 不标边界); 表格用于总结收口, 不打断叙事
- 讨论过程可以留痕 (问答式演化的认知轨迹有价值)
- 编号: `01_Title_Case.md` 建新号, 主题不复用; 老条目内容可自由改写 (观点可后悔)
- 每条 entry 尾部 `## 挂钩` — 影响哪些标的 (纯指针)
- 内容主权在用户 (立条目/改观点, 无门槛); 用户定期发起整理, LLM 执行 (合并重复 / 拆分过长 / 修指针)

## 三、参与 L4 裁决 (共振机制 — a 标的调研影响 b 标的分析)

建新链或全链重跑时, L4 开工前加一步 **KB 扫描**: LLM grep 各 entry 的 "挂钩" 小节, 找出与该标的相关的用户偏好条目, 作为**用户输入**进入 L4 裁决 — 与 LLM 的独立分析结论并置, L4 综合两者。

- 进 L4 的形态: 引用 KB 条目号 + 用户观点一句
- **KB 是输入不是改写权**: 链的裁决仍由框架产出, 用户的 KB 观点作为一路输入参与
